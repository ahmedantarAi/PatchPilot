| D-32 | Phase 3a eval harness implementation: 1. | D-34 | Phase 4 LangGraph pipeline (`analyze -> propose <-> verify -> report`): 1. `analyze` runs `ast.parse` for syntax validation, `ruff check --output-format json --isolated` in an isolated temp directory without reading target-repo configuration (Ruff 0.17.3 uses `--isolated` to ignore config files per SPEC §3), queries Qdrant vector store when healthy, and executes LLM diff/fault analysis via `LLMProvider` respecting `data_class` to emit typed `Finding` objects (`file`, `line`, `category`, `explanation`, `fixable`). 2. `propose` supports both raw unified diffs and `SEARCH/REPLACE` blocks, normalizing to canonical unified diffs via `difflib.unified_diff`. 3. `verify` executes patches in single fresh sandbox containers via `SandboxRunner`; bounded retry loop (`verify -> propose`) caps at `k = 3` attempts, feeding test failure output back to `propose` and tracking `pass@1` and `pass@3`. 4. `report` emits only patches achieving `verified = True` (`reported_patch = ""` when unverified). 5. Retrieval implemented via `Embedder` protocol (`HashEmbedder` for deterministic 64-dim test/CI vectors, `OllamaEmbedder` for live) and plain `httpx` Qdrant client (`QdrantStore`), degrading gracefully when Qdrant is unreachable. 6. `python -m patchpilot run --case <case> --provider <provider>` satisfies PLAN.md Phase 4 acceptance contract both when Qdrant is up and when Qdrant is down. (**Note:** the initial 5-case live check reported during D-34 is marked **INVALID** because it used leaked `target_file` names read from `meta.json`; superseded by D-35.) | Phase 4 LangGraph pipeline implementation |
| D-35 | Phase 4 contamination & isolation fixes: 1. **Ground-truth isolation:** `_load_case_files` loads only `repo/` files; reading `patch.diff` / `meta.json` is isolated inside `load_mock_ground_truth` and called exclusively on the `mock` provider path (and in test assertions). Removed `target_file` from `PipelineState` and from all prompts; `analyze` localizes faults from the repo non-test `.py` file list, failing test output, and file contents, and the model chooses the file itself in multi-file repos. 2. **Reward-hacking guard:** Rejects any patch touching a test file (`test_*.py`, `*_test.py`, anything under `tests/`, `conftest.py`) or any non-`.py` file both at normalization time (`normalize_patch`) and inside `verify` (defense in depth); rejected patches count as failed attempts with the rejection reason fed back to `propose`, and assertion-editing patches never produce `verified = True`. 3. **Qdrant per-case isolation:** Each case uses a collection named from its content hash (`patchpilot_case_<sha256[:16]>`), recreated before indexing and deleted in `finally` after the run so retrieval for case B never returns chunks from case A. 4. **Leak regression test:** Recording fake provider captures every prompt on `seeded_eval` and asserts zero `meta.json` target-file leaks (unless legitimately in failing test output), zero fix hunk lines, and zero `patch.diff` content. 5. **Live smoke test re-run (`n=5`, smoke test only, not an eval result):** Earlier 5/5 live check marked invalid; re-running `seeded_eval/0001..0005` with `qwen2.5-coder:7b` without ground-truth leakage yielded smoke test `pass@1 = 3/5 (60.0%)`, `pass@3 = 4/5 (80.0%)` (case 0003 failed 3 attempts; case 0005 failed attempt 1 and passed on attempt 2). | Phase 4 contamination fixes |
| D-36 | Phase 5 Langfuse v4 tracing & container memory budget: 1. **OTLP trace ingestion & dataset sync (`src/patchpilot/tracing.py`):** Langfuse v4 (`4.72.0`) runs in `events_only` ClickHouse mode and rejects legacy `/api/public/ingestion` events, so `PatchPilotTracer` exports one root span per case run plus child spans for each graph node (`analyze`, `propose`, `verify`, `report`), each LLM call (`model`, `prompt_tokens`, `completion_tokens`, `total_tokens`, `latency_s`), and each sandbox verification run via OTLP/HTTP JSON (`POST /api/public/otel/v1/traces`), verifies ingestion via `GET /api/public/v2/observations?traceId=<id>`, and syncs dataset runs via `/api/public/v2/datasets`, `/api/public/dataset-items`, and `/api/public/dataset-run-items`. Secrets are read only from env via `LangfuseSettings` (`LANGFUSE_INIT_PROJECT_PUBLIC_KEY` / `LANGFUSE_INIT_PROJECT_SECRET_KEY` headless bootstrap fallback) and redacted in `__repr__`/`__str__`. 2. **`langfuse-web` V8 heap & measured memory (`docker-compose.yml`, `SPEC.md` §8):** At `mem_limit: 1024m`, Node.js in `langfuse-web` defaulted V8's old-space limit to ~512 MB and hit a V8 heap OOM at 517 MB during Next.js route compilation.
